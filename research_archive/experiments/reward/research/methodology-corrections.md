# 方法修正：哪些旧结论已作废或被收紧

## 1. 离线 top-k 不是回测

早期曾出现“按每日期末分数选 TopK，再聚合未来收益”的分析。它可以说明分数横截面排序信息，但不包含：

- `lag: 1`；
- T+1；
- 涨跌停、停牌、一字板、价格跳变；
- 100 股整手；
- 同一股票重叠持仓；
- 交易成本；
- 卖出受限；
- 现金和仓位容量。

因此此类结果统一标为诊断，不得称作 backtest。正式收益只认 QuantX run 工件。

## 2. 标签 horizon 与执行 holding 必须对齐

2026-07-20 的 3D 重跑发现，先前把 3D label 与 H5 持有期混在一起解释，会把标签外第一天收益误归因给模型。此后规则为：

- score 的训练 horizon；
- 回测入场时点；
- 持有天数；
- target 的起点；

必须同时写进实验合同。任何一个改变都需要重新标记结果，不能沿用旧结论。

## 3. 评分 artifact 必须覆盖完整横截面

早期 50k 行或少日期诊断存在明显时间偏差，不能作为全市场结论。正式 artifact 必须：

- 覆盖所声明区间所有 signal date；
- 覆盖选择 universe 中可评分股票；
- `(signal_date, instrument)` 唯一；
- 有 JSON manifest；
- 包含 checkpoint、scaler、fold、score 列、覆盖度和 DDP 信息。

## 4. checkpoint 只由历史 validation 选择

不能查看 2020–2026 QuantX 结果后再选择 epoch、持有期、阈值或架构。旧多任务 Reward
epoch10 在 2019 `validation_select` 下冻结；当前 H7 absolute full-pair v1 同样坚持
训练/验证与 2020+ score 导出、QuantX 回测分离。

## 5. 单资产退出不等于组合风险控制

止损、止盈、移动退出能改变单笔路径，但如果弱市中卖出后又换入同一分数体系的弱股票，它们无法去除共同 beta。市场宽度/AMV 也同理：解释回撤不等于拥有可交易的提前开关。

## 6. 容量、初始资金与权重语义必须显式

同一 score 的 Top1、Top5、Top10 和分位策略不是同一个问题：

- 容量改变单票暴露；
- `cash_equal` 与 `target_weight` 不等价；
- 初始资金过小会让高容量策略无法买足整手；
- `max_positions` 与 `selector.topk` 不一致时，候选数和实际持仓数不同。

当前最终 Reward 使用 `portfolio_target`、Top5、单仓 22% 上限；弱转强使用 Top4 候选、最多 5 仓。

## 7. 共享仓位融合与净值组合不可混为一谈

静态 sleeve 的低相关性结果不能推导出同账户抢仓有效。后续 F0/F1/F2 已直接否定该推断。研究报告必须说明组合是：

```text
静态初始资金分配、不再平衡、无现金互转
```

## 8. 结果语言

推荐使用：

- “在冻结区间和执行合同下观察到……”
- “正式 QuantX 结果支持/不支持……”
- “离线诊断显示……，但尚未证明可交易性。”

禁止使用：

- “模型预测了未来收益，因此策略有效。”
- “离线 IC 为正，因此可以部署。”
- “某次 target OOS 为正，因此跨期可泛化。”
