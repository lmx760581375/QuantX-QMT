1. head 输出 logit；
2. 先经过 sigmoid；

4. 在候选池内对 Sharpe/Drawdown 做 rank；
5. 生成最终 `reward_return_topn_risk_score_7d`。

```text
score = 0.8 * return_logit + 0.2 * drawdown_logit
```

之前的 5050 也是直接对 raw logits 做线性组合。之后虽然补做了 two-stage，但当前只有 drawdown，没有 Sharpe，因此仍然不是旧 baseline 的完整 contract。

我建议目前按下面的优先级判断问题来源：

1. **日线 AE candidate 被置零**
   这是已经确认的输入契约变化，不是猜测。

2. **Reward Transformer 容量和 head 改变**
   512/6/8/2 与 768/7/12/3 不是同一个模型容量。

3. **监督目标和 pair 构造不同**
   当前双 AE 不一定真的在学原日线 H7 目标。

4. **分钟 token 造成噪声或污染日线表征**
   这是合理假设，但目前还没有和前面三项完全隔离。

5. **分钟压缩率不够**
   64 个 token × 128 维不一定够，也可能相反：压缩后的 token 保留的是噪声。

### 最小化的拆解实验

不建议现在直接继续调分钟 AE 压缩率。更合理的顺序是：

1. 用当前 Fusion Reward 结构，先做 **daily-only**；
2. daily-only 分别比较：
   - candidate 全零；
   - 使用真实 candidate；
3. 统一成旧日线 H7 close-to-close 标签和 pair contract；
4. 把 Reward 容量先对齐到 768/7/12；
5. 在 daily-only 能稳定后，再加入 64 个 minute token；
6. 最后才比较 5 分钟、15 分钟和不同 latent token 数量。

这样能把问题拆成：

```text
日线 AE 输入分布
→ Reward 模型容量
→ 监督目标
→ 分钟 token 增量
→ 分钟压缩率
```

> 在不加入任何分钟 token 的情况下，只使用当前双 AE 的 daily 分支，它能不能复现日线 Reward 的基本效果？

### 当前 pair 的构造方式

pair 都限制在同一个 signal date 内，不跨日期。

#### Return pair

- 从同一天的股票中选择一个 `good` 样本；
- 在同一天寻找 return 更差的 `bad` 样本；
- 要求 return 差异至少为 `0.005`；
- 每次训练时从该 good 对应的同日 bad pool 中按 seed 动态采样一个 bad；
- 训练目标是：

```text

```

#### Drawdown pair

- 先按 drawdown quality 分成上下分位；
- good 来自较优 drawdown 组；
- bad 来自较差 drawdown 组；
- 同时限制两者的 return 差距不超过 `0.005`，避免模型只靠 return 区分；
- 每个 drawdown anchor 预生成 4 个 bad options；
- 每个 epoch 根据 seed 选择其中一个。

```text

drawdown pair
```
