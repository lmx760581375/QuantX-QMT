核心结构是：

```text
冻结 AE 表征
    ├─ quality head: q，预测可成交条件下的 5 日排序质量
    └─ fill head:    f，预测 T+1 按原规则可成交的概率 p = sigmoid(f)

最终排序分数：s = q + log(p)
```

其中 `log(p)` 会压低模型认为更可能被拒单的股票；QuantX 在实际执行时仍使用原来的 `0.095`、涨停、停牌等规则兜底。

训练时同时有三种 loss：

```text
L = L_pair + λ_list * L_list + λ_fill * L_fill
```

- `L_pair`：保留现有 Bradley-Terry pairwise loss，但 pair 两端都必须是真实 `T+1` 可成交样本。它维持全局、稳定的相对排序能力。
- `L_fill`：对所有候选做 `BCEWithLogits(f, fillable)`，让模型从 `T` 的特征预测次日是否会被原执行规则拒绝。
- `L_list`：每次取同一个信号日的一小组股票，直接优化这一组内的最终排序分数 `s`。

`L_list` 我建议用 sampled ListNet，而非 ListMLE 或硬 Top5 分类。形式是：

```python
# [batch_dates, list_size]
p_fill = sigmoid(f)
score = q + log(clamp(p_fill, min=eps))

# 只对真实可成交股票分配目标概率；净收益越高，目标质量越大

                        mask=fillable)

# 预测分布仍包含不可成交股票，因此会直接惩罚它们排在列表前部
loss_list = -sum(target * log_softmax(score / score_temperature))
```

这里最关键的一点是：`target` 只在真实可成交股票之间归一化，但 `log_softmax(score)` 包含整张候选列表。这样一只不可成交股票若被排到前面，会抢走可成交高收益股票的概率质量，产生明确梯度把它压下去。

```python
q, f = model(one_day_features)       # [N]
score = q + F.logsigmoid(f)          # 最终用于排序的分数
```

```text
π = 按 net_return_5d 从高到低排序的 fillable 股票
```

我建议用加权、截断的 ListMLE：

```text
L_list(t) =
  - Σ[j=1..K_list] w(j) *
    [ s(π_j)/τ - logsumexp(s(remaining candidates)/τ) ]
```

其中：

- `π_j`：真实可成交收益第 `j` 名；
- `remaining candidates`：尚未被取走的全部股票，包含真实不可成交股票；
- `w(j) = 1 / log2(j + 1)` 或等价 DCG 权重，第一名权重最大；
- `K_list = min(ceil(2% * N_fillable), 100)`，而不是只做真实 Top5。

这表示：

- 真正的第一名必须压过当天所有其他候选；
- 第二名必须压过除第一名外的所有候选；
- 越靠前权重越大；
- 不可成交股票如果预测分数过高，会出现在每个高位候选的分母中，直接增加 loss，被压低；
- 尾部不强行要求精确排列，降低噪声和此前 tail-only 失败的风险。

每个交易日是一张列表。模型对当天全部股票输出一个 `score`，将其转成预测排名分布：

```text
P_model(i | day) = softmax(score_i / τ_model)
```

然后用真实的“可成交后 5 日净收益排名”构造目标分布：

```text
P_true(i | day) ∝ 1 / rank_i^γ
```

`rank=1` 的真实第一名质量最大，后面按幂律下降；`γ` 越大，目标越强调前排。最后做交叉熵：

```text
L_list = - Σ_i P_true(i) * log(P_model(i))
```

这就是“预测 score 形成的排序分布”拟合“真实排名形成的排序分布”。它是可微的，且天然让前面的真实股票拿到更大的训练权重。

一个很重要的修正是：**不可成交股票不应设为收益 0。**

反例很直接：

```text
A：T+1 不可成交，未来收益 +10%，标签若设为 0
B：T+1 可成交，5 日收益 -1%

按 0 标签，A 会排在 B 前面。
```

这会让模型主动把拒单股票排到前面，正好反过来伤害 `Fill@5` 和实际可交易 precision。只有当策略显式支持“空仓”这个可选动作时，0 才有“持有现金”的含义；现有 Top5 策略没有把 cash 当作可排序候选，拒单还会占掉一个选股名额。

因此单 head 的正确标签定义应该是：

```text
真实可成交股票：
  按 T+1 成交后的 5 日净收益排序，得到 rank_i

真实不可成交股票：
  P_true(i) = 0
```

注意这里的“0”是**目标概率为零**，不是“收益标签等于 0”。预测分布仍包含全部股票：

```text
P_model = softmax(all stocks' score)
P_true  = normalize(rank_weight * fillable)
```

所以不可成交股票如果预测分数高，会拿走 `P_model` 的概率质量，却没有任何 `P_true` 质量，交叉熵会直接把它压下去。

pairwise 可以完全保留，且不需要第二套前向：

```text
当天所有股票一次前向，得到 score[N]

L_pair：
  沿用原 up / range / down 分类及 pair 抽样，
  但 pair 两端限定为真实可成交股票。

L_list：
  用当天全体股票的 score，
  拟合真实可成交股票的 rank distribution。

L_total = L_pair + λ_list * L_list
```

这样一个 `score` 同时承担两件事：

- 在可成交股票之间按 5 日收益排序；
- 将预计会在 T+1 被原执行规则拒绝的股票压到列表后面。

工程上，每个交易日就是一个逻辑 batch；每天股票数不同则 padding 加 mask。若显存不足，仍以“一天”为损失单位，前向可分微批收集 score，再统一计算该日的 listwise loss。

我建议首版目标分布只使用 rank，不直接使用收益绝对值：

```text
P_true(i) ∝ rank_i^(-γ)
```

这样严格检验“listwise 排名是否优于 pairwise”，不会让极端涨停收益主导 softmax。`γ` 固定后不在 2019 或 2020+ 上调参。

```text

y_i = 0,                                  其他股票

L_top20 = -sum(y_i * log softmax(z_i))
```

所有股票仍在 softmax 分母中，所以非 Top20 仍会被压低；但目标质量中 Top5 变为：

```text

```

而不是当前约 26%-28%。这才是把训练重点从“完整排序”移到“最终 Top5 附近”，且不引入第二个 head、不改推理合同。

2. 加 `TopK boundary hard-negative loss`，替代或大幅弱化当前宽泛随机 pairwise。

每个日期：

- 正样本：真实可成交 Top20；
- 负样本：模型当前预测 Top20 中、但不在真实 Top20 的股票；
- 额外负样本：真实 rank 21-100 的股票。

核心是惩罚“看起来分很高、但不应进入交易池”的股票：

```text
L_boundary = mean(softplus(-(z_positive - z_hard_negative)))
```

这直接训练第 5 名附近的决策边界。当前的随机 pairwise 可能花很多更新在“第 1,500 名应高于第 1,800 名”，对 Top5 没有实际价值。

3. 用同一个 score 加 TopK 可成交性约束，不加第二个 head。

只取“当前预测 Top20 里的不可成交股票”作为 hard negative，让它们低于可成交 Top20 的边界分数：

```text
L_fill = mean(relu(z_rejected_top20 - z_fillable_boundary + margin))
```

它比当前 `y=0` 的隐式压低更直接针对 `Fill@5` 和 `price_jump` 拒单。模型仍只有一个分数，最终仍按该分数排序。

4. utility 只作为可选的次级权重，不是主目标。

它可以用于给 `L_boundary` 的 pair 加 clipped return-gap 权重，例如高收益 Top5 被低收益候选挤出时处罚更大。但不该直接用未裁剪 raw return softmax，否则会追逐少数极端涨停收益，方差可能更大。

**建议的损失形式**

```text
L = 1.0 * L_top20
  + λ_boundary * L_boundary
  + λ_fill * L_fill
  + λ_pair * L_pair_broad
```

其中 `L_pair_broad` 保留为小权重的全局排序正则，不再和 TopK 目标平权。具体权重不应靠 2020+ 调，应在 pre-2020 验证折比较。

**验证顺序**

先做严格消融，不直接押新 loss：

1. `pairwise-only`：同模型、同数据、同 seed、同 20 epoch。
2. 当前 `full-list rank^-1 + pairwise`。
3. `Top20 truncated listwise + boundary hard negatives`。
4. 第 3 项再加 `L_fill`。

2019 不能只看 exact P@5，应按日 bootstrap 比较 `effective_net_return@5`、Fill@5、Top20 收益和回撤代理。只有这些都优于 pairwise-only，才用一次未参与选择的后续时间段跑 QuantX。

所以核心结论是：不是“把 rank 换成 utility”会解决问题，而是当前 loss 把太多学习能力花在 Top5 之外，且没有专门惩罚会挤掉 Top5 的高分错误候选。

## Codex — 2026-07-21T06:11:05.622Z

`net@5` 是离线 Top5 的“有效净 5 日收益”代理，不是最终 QuantX 账户收益。

对某天模型预测的 Top5：

```text
若该股票 T+1 可成交：
net_5d = (1 + raw_5d_return) * (1 - 0.0015) * (1 - 0.0016) - 1

若不可成交：
net_5d = 0
```

其中：

- `0.0015`：买入侧 `0.10%` 滑点 + `0.05%` 佣金；
- `0.0016`：卖出侧 `0.10%` 滑点 + `0.05%` 佣金 + `0.01%` 印花税；
- 每日对 Top5 五个位置求平均，再跨日期平均；
- 不可成交股票按收益 `0` 计入分母，因此它同时反映收益与 Fill。

它和 `entered_gross_return` 的区别是：后者只对真正成交的股票算 raw return，不处罚拒单和成本。`net@5` 更接近“如果每天机械持有五天”的单票收益代理，但仍不能替代 QuantX：正式回测还包含 H4 出场、持仓重叠、现金、卖出拒单与实际订单顺序。训练继续在 8 卡运行。

## Codex — 2026-07-21T07:24:16.922Z

结论：应放弃当前的 hard Top5 swap loss。它的训练 loss 在降，但 `net@5` 不升，而且把拒单人为设成 `min(valid)-2%`，与“买不进就是现金收益 0”的执行语义不一致。

我建议的目标是“精确可执行 H5 utility + 可微 SoftTop5 组合收益”。

当前 H5 收益本身已对齐 `T+1 close -> T+5 close`，不必重建基础 memmap；见 [target_paths_meta.json](${HOME}/git/quantization/QuantX-QMT-qmt-mac/tmp/weak-to-strong-diffusion-v1/market_all_close2close_balanced_v2/data/target_paths_meta.json:1)。需要新建的只是按最终 QuantX 配置计算的 utility 表：

\[
u_i =
\begin{cases}
\text{T+1 买入、T+5 卖出后，扣滑点、佣金、印花税、手数的净收益}, & \text{可成交}\\
0, & \text{拒单}
\end{cases}
\]

可成交必须复用 Executor 规则：停牌、涨停、一字板、价格跳变。若最终策略采用创业板/科创板的 `19.5%` 阈值，就将执行配置和标签同时固定为 `price_jump_limit: board_limit`；不能只改标签或只改回测。当前标签仍是统一 `0.095`，见 [build_execution_labels_v1.py](${HOME}/git/quantization/QuantX-QMT-qmt-mac/tmp/reward-model-listwise-v1/build_execution_labels_v1.py:78)。

保留一个 score head，每天完整横截面一个 batch。主损失改为：

\[
w=\operatorname{SoftTopK}(s,K=5),\quad \sum_i w_i=5
\]

\[
L_{\text{return}}=-\frac{1}{5}\sum_i w_i\tilde u_i
\]

其中 \(\tilde u\) 是仅训练时做过训练集分位裁剪的 utility，降低极端涨停尾部噪声；验证仍用原始净收益。`SoftTopK` 用 sigmoid 阈值加可微 Newton 求解实现，不需要新依赖，也不会有 SoftSort 的 \(O(N^2)\) 内存。

再加一个明确的成交率约束，而不是把拒单伪造为负收益：

\[
F=\frac{1}{5}\sum_iw_i\mathbf1_{\text{fillable}}
\]

\[
L_{\text{fill}}=\lambda_f[\max(0,0.9671-F)]^2
\]

`0.9671` 是 epoch010 的 `Fill@5`。这样模型只有在不牺牲基线成交率的前提下，才追求更高 Top5 净收益。

原来的 pairwise 不删，但降为锚定项：

\[
L=L_{\text{return}}+L_{\text{fill}}+0.1L_{\text{pair}}
\]

`L_pair` 仍可用 up/range/down 做分层采样，但 pair 的正负方向改为按精确 `u`，并聚焦真实 Top20 与 Top5 边界，避免全市场粗分类压过目标。

这比当前 hard swap 更合理，因为它直接优化“预测 Top5 的平均可交易净收益”，对 cutoff 附近全部候选都有稳定梯度，不会只优化一对漏选/误选股票，也不会违背拒单等于现金的定义。

实施会保持最小改动：

- 新建 `tmp/reward-model-softtopk-v1/`，不改 RL 买入、卖出、替换模型。
- 复用现有 daily batch、AE、单 score head 和 epoch010 checkpoint。
- 新增 utility 标签表与 SoftTopK loss，不改原始特征和收益 memmap。
- 用 6 卡从 epoch010 微调 6 个 epoch，每 epoch 固定评估 2019。
- 仅当 `net@5 > +0.949%`、`Fill@5 >= 96.71%` 时，才进入 2020-2026 回放。

这不能保证 H5 本身存在足够预测信号，但它会首次让训练目标与实际业务目标严格一致。确认这个方案后，我再开始写代码。
