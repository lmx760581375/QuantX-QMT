## Codex — 2026-07-24T11:27:52.860Z

这个模型本体从 [multiscale_model.py:63](${HOME}/git/quantization/CellTransformer/models/multiscale_model.py:63) 开始；你标注的第 79 行是在创建最后的预测头，不是模型主体的起点。

它可以理解为“带快、中、慢三套循环记忆的 latent-memory Transformer”：

```text
输入 x [B, T, input_dim]
  -> InputEncoder
  -> [B, T, D]
  -> MultiScaleNeuronBlock × depth
  -> [B, T, D]
  -> PredictionHead
  -> prediction [B, output_dim]
```

其中 `B` 是 batch，`T` 是序列长度，`D=hidden_size`。默认输入编码器会做线性投影、正弦位置编码、RMSNorm 和 dropout；padding 位置会置零。

每个外层 block 都有自己独立的内部神经状态 [neural_dynamics.py:80](${HOME}/git/quantization/CellTransformer/models/neural_dynamics.py:80)：

```text
fast / medium / slow state: [B, R, N, D]
R = num_neurons
N = num_cells
```

一个 block 会重复 `thought_steps` 次内部推演：

1. 将快、中、慢状态按可学习权重混合。
2. 每个 neuron 用 attention 从自己的 `N` 个 cell 中汇聚出 activity。
3. 每个 cell 再通过 attention 读取所有 neuron 的 activity，形成跨 neuron 的 synaptic message。
4. cell 状态结合 neuron role、synaptic message，并经过：
   - cell 内部 self-attention
   - 对输入序列的 cross-attention
   - SwiGLU FFN
   生成候选状态和写入门。
5. 三套状态按不同时间常数更新：

```text
alpha_s = 1 - exp(-delta_t / tau_s)
state_s = state_s + write_gate * alpha_s * (candidate_s - state_s)
```

默认 `tau=(1, 4, 16)`，因此 fast 变化最快，slow 最稳定；`tau` 和混合权重都可设为可学习。相关积分逻辑在 [multiscale_integrator.py:37](${HOME}/git/quantization/CellTransformer/models/multiscale_integrator.py:37)。

完成内部推演后，三套状态再次混合并展平成 `[B, R*N, D]` 的 memory。原始输入 token 以该 memory 为 key/value 做一次 write-back cross-attention，得到该 block 的输出 `[B,T,D]`。因此，token 间的信息主要通过共享的内部 memory 间接交互，而不是标准 Transformer Encoder 那种直接 token-to-token self-attention。

最后，第 79 行构造的 `PredictionHead` 会对 token 维做 `mean` 或取第一个 token，再 RMSNorm 和线性投影：

```text
[B, T, D] -> [B, D] -> [B, output_dim]
```

几点实现上的关键含义：

- 每个外层 block 的内部状态相互独立，但都会串联处理 token 表示。
- 每次 `forward` 结束会默认把本 batch 的最终状态提交到 runtime memory；下一次 forward 会从“学习到的种子 + runtime delta”开始。因此它并非严格无状态，推理顺序和 batch 组成可能影响后续结果。可通过 `reset_runtime_state()` 或冻结更新控制。
- `task_type` 在这个模型主体中不决定激活函数；预测头输出始终是线性值/logits。
- 使用 `pooling="mean"` 且存在不同有效长度的 padding 时，padding 虽被置零，但仍参与平均分母；变长序列场景需要留意这一点。

核心设计目标是：用显式、多时间尺度的循环记忆替代单纯堆叠 token attention，让模型既能反复读取输入，也能保留短期和长期的内部动态。

## Codex — 2026-07-24T11:30:17.090Z

对，但要区分“本次 forward 的临时 state”和“跨 forward 的 runtime state”。

每次 `forward` 开始都会重新构造 `fast/medium/slow` 临时状态，不过初始值是：

```text
learned state_seed + runtime_delta
```

而不是单纯回到 `state_seed`。在 forward 结束时，默认会把当前 batch 最终状态的均值写回 `runtime_delta`，所以下一次 forward 会受到前一次影响。它不是逐样本直接续接，而是以 batch 聚合后的状态作为跨调用记忆。

训练和推理都会动态更新。代码没有用 `self.training` 限制 `_commit_runtime_state()`，默认 `_runtime_updates_enabled=True`；`model.eval()` 只会关闭 dropout 等训练行为，不会冻结 runtime state。该提交本身在 `no_grad` 下执行，不参与反向传播，也不进 checkpoint（buffer 设置了 `persistent=False`）。

控制方式：

```python
model.set_runtime_state_updates(False)  # 后续 forward 不再提交新 state
model.reset_runtime_state()             # 清空 runtime_delta，下一次从 learned seed 开始
snapshot = model.snapshot_runtime_state()
# 推理
model.restore_runtime_state(snapshot)   # 事务式恢复，避免推理污染状态
```

因此同一模型实例上，训练和推理混用会相互影响 runtime state；验证/部署时通常应冻结、重置，或使用 snapshot/restore。

## Codex — 2026-07-24T11:39:26.820Z

锐评结论：思路有研究价值，但当前最大硬伤是把“跨 batch 的全局状态”设成默认行为。对严格连续、单一实体流的数据可能有效；对随机 mini-batch、独立样本、金融横截面或在线多请求场景，风险明显大于收益。

- `P0` 全局 state 污染样本。runtime state 的形状不含 batch 维度，初始 state 来自 `seed + runtime_delta`，[`_initial_state`](${HOME}/git/quantization/CellTransformer/models/neural_dynamics.py:175)；结束后又把整个 batch 的最终 state 求均值写回 [`_commit_runtime_state`](${HOME}/git/quantization/CellTransformer/models/neural_dynamics.py:198)。这意味着样本 A 的输出会受“上一批有哪些样本、batch 如何分组、调用顺序”影响，但 state 没有按股票、用户、文档或 episode ID 隔离。

- `P0` 该跨 batch 记忆是 detached 的，不能端到端学习。写回在 `no_grad` 下完成，下一批只读取上批的 detached 均值。因此它既引入跨 batch 依赖，又没有跨 batch 的梯度信用分配，容易成为输入分布的随机漂移器，而不是真正可学习的长期记忆。

- `P1` 训练和推理默认都会写 state，且不随 `eval()` 自动冻结。forward 无条件调用提交逻辑，[`neural_dynamics.py:253`](${HOME}/git/quantization/CellTransformer/models/neural_dynamics.py:253)。同一个请求换个执行顺序或并发顺序，结果可能不同；runtime buffer 还是 `persistent=False`，断点恢复也无法复现精确状态。多个通用测试都显式关闭该功能，例如 [`test_model_forward.py:31`](${HOME}/git/quantization/CellTransformer/tests/test_model_forward.py:31)。

- `P1` “多时间尺度”更像内部迭代次数，不是真正按序列时间演化。每个 thought step 都读取完整输入序列，而不是沿 `T` 逐步推进；`delta_t` 也是每个样本一个值，不能表达序列内不规则时间间隔。若目标是时间序列预测，这个名称容易让人高估它的时间建模能力。

- `P1` 没有因果约束。内部 cell 对完整 `inputs` 做 cross-attention，只传了 padding mask，[`cell_transformer.py:39`](${HOME}/git/quantization/CellTransformer/models/cell_transformer.py:39)。用于分类可以；用于 next-token、在线预测或金融未来收益预测时会直接看到未来 token，必须额外处理 causal mask。

- `P1` 固定 latent bottleneck 可能丢失细粒度序列关系。全部 `T` 个 token 被压进 `R*N` 个 memory slot，默认是 `8*8=64`；最终每个 token 再读取同一份 memory。长序列、局部对齐、逐 token 标注任务很容易被这个瓶颈限制。

- `P2` 计算并不轻。每个 block 的每个 thought step 都把输入复制给每个 neuron，并执行 `transition_depth` 次 cell-to-input cross-attention，[`cell_transformer.py:120`](${HOME}/git/quantization/CellTransformer/models/cell_transformer.py:120)。默认参数下，一个外层 block 等价于对输入做 `4 * 2 * 8 = 64` 组 neuron-input 读取；四层就是 256 组。它避开了纯 `T^2` 的 token self-attention，但 `R * N * T * thought_steps * depth` 的代价和显存压力不小。

- `P2` 三个尺度未必会真正分工。三套 state 共用 write gate，候选状态主要靠 scale embedding 区分，[`cell_transformer.py:143`](${HOME}/git/quantization/CellTransformer/models/cell_transformer.py:143)。`tau` 只保证更新速度不同，没有多样性、去相关或职责约束，训练后很可能得到三个高度相似的 state。

- `P2` 变长序列下 `mean` pooling 有明确偏差。padding 会被置零，但预测头直接对所有位置求平均，[`heads.py:24`](${HOME}/git/quantization/CellTransformer/models/heads.py:24)。有效内容相同、padding 更多的样本会得到不同缩放的表示。

我的判断是：把 runtime state 默认关掉时，它是一个复杂但可实验的“循环 latent-memory 编码器”；默认打开时，它更像一个没有样本身份和生命周期管理的全局缓存。是否值得保留，关键不在模型是否复杂，而在消融实验能否证明：严格按实体和时间顺序输入时，runtime state 相比冻结 state 有稳定、显著且可复现的增益。
