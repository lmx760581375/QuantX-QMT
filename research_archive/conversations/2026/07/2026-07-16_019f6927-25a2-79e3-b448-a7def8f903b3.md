**4. Label 设计**



**5. 模型结构**

先做两个非深度 baseline，再上轻量序列模型。

Baseline 1：Logistic Regression / Ridge classifier

输入为 60 日序列 flatten 后的统计摘要，验证 label 是否可学。

Baseline 2：LightGBM / ExtraTrees

输入为最后一天滚动特征 + 横截面 rank，不用复杂序列结构。若这个都学不到，深度模型大概率只是过拟合。

主模型：Kronos-inspired Small Transformer Classifier

```text
Input: [batch, 60, feature_dim]
Linear(feature_dim -> d_model)
Positional Encoding
TransformerEncoder x 3
Pooling = last_token concat mean_pool
LayerNorm
MLP Head
Output logits: [SELL, HOLD, BUY]
```

首版参数：

```text
d_model = 96
n_heads = 4
n_layers = 3
ffn_dim = 192
dropout = 0.10
head_hidden = 128
参数量目标 1M-5M
checkpoint 约 5MB-30MB
```

备选模型：TCN Classifier

```text
1D causal conv blocks
kernel_size = 3
channels = 64/96
dilation = 1,2,4,8
global average + last token pooling
classification head
```

TCN 训练更快，可作为 Transformer 的效率对照。

规则：

```text

      break
```

**7. 模型具体结构**

首版主模型用 Small Transformer，不做原版 Kronos tokenizer。

```text
Input [B, 60, 52]
  -> Linear(52, 96)
  -> LayerNorm(96)
  -> learned positional embedding [60, 96]
  -> TransformerEncoder x 3
       MultiHeadAttention(d_model=96, heads=4)
       FeedForward(96 -> 192 -> 96)
       GELU
       Dropout(0.10)
       Pre-LayerNorm
  -> pooling:
       last_token [B, 96]
       mean_pool  [B, 96]
       concat     [B, 192]
  -> LayerNorm(192)
  -> MLP head:
       Linear(192, 128)
       GELU
       Dropout(0.10)
       Linear(128, 3)
```

参数量估算：

```text
Input projection:
  52*96 + 96 ≈ 5,088

Position embedding:
  60*96 ≈ 5,760

单层 Transformer:
  QKV + out ≈ 4 * 96 * 96 = 36,864
  FFN ≈ 2 * 96 * 192 = 36,864
  LayerNorm/bias 约 1,000
  单层约 75k

3 层约:
  225k

Head:
  192*128 + 128*3 ≈ 25k

总参数:
  约 260k-300k
```

这个比 11MB checkpoint 更小。若要贴近 5-10MB checkpoint，可以用 base 配置：

```text
d_model = 192
heads = 6
layers = 4
ffn_dim = 384
head_hidden = 256
参数量约 1.8M-2.2M
checkpoint 约 8-12MB
```

推荐实际训练顺序：

```text
先跑 small:
  d_model=96, layers=3, params≈0.3M
  用来验证数据和 label pipeline

再跑 base:
  d_model=192, layers=4, params≈2M
  用来对齐 Kronos 轻量 checkpoint 体量
```

训练配置：

```text

gamma = 2.0
optimizer = AdamW
lr = 3e-4
weight_decay = 1e-4
batch_size = 512
epochs = 20
```

训练采样：

**一、核心存储设计**

```text
先 clip 到训练 token 的 0.5% / 99.5% 分位
再 standardize
rank 特征不 standardize 或只做轻微中心化
```

**九、训练读取性能**

memmap 最大风险不是磁盘大小，而是随机小切片太多导致 I/O 退化。因此 sampler 要设计好。

不要完全随机 sample。

推荐 `BalancedBlockSampler`：

```text
1. 按 label 分桶: BUY / HOLD / SELL
2. 每个 epoch 对 BUY、SELL 全量或近全量采样
3. HOLD 分层下采样
4. 采样完的 index 先按 (instrument_idx, date_idx) 排序成小 block
5. block 顺序 shuffle
6. block 内保持相近 instrument/date，提高 memmap 局部性
```

batch 示例：

```text
block_size = 8192 samples
batch_size = 512
```

这样既有随机性，也减少磁盘 seek。

DataLoader：

```text
num_workers = 0 或 2 起步
persistent_workers = True
pin_memory = 有 GPU 时 True
prefetch_factor = 2
```

如果 CPU 训练，`num_workers=0/2` 对比测试，不盲目开很多 worker。多个 worker 同时随机读 memmap 可能更慢。

Dataset 初始化时：

```python
features = np.memmap(path, dtype=np.float16, mode="r", shape=(I, T, F))
labels = np.memmap(path, dtype=np.int8, mode="r", shape=(I, T))
```

`__getitem__` 返回前：

```python
x = np.asarray(x, dtype=np.float32)
x = np.clip(x, clip_low, clip_high)
x = (x - mean) / std
```

`cross_section_mask` 是“横截面有效证券掩码”，用于告诉模型横截面张量里哪些位置是真实、可用的数据，哪些只是补齐位或无效位。

例如横截面输入按固定股票池大小 `N=5000` 保存：

```text
x_cross_section.shape = [5000, F_cross]
cross_section_mask.shape = [5000]
```

某交易日实际上只有 4,200 只股票满足可交易、数据完整等条件，那么：

```text
cross_section_mask[:4200] = True
cross_section_mask[4200:] = False
```

模型在做 attention、均值池化、横截面归一化等操作时，必须忽略 `False` 的位置。否则用于对齐固定 shape 的零填充，或停牌、退市、缺失特征的证券，会被模型误认为真实的市场信息，造成统计偏差。

它通常同时覆盖这些情况：

- 当日不在可用股票池中的证券；
- 停牌、上市天数不足或不符合交易过滤条件的证券；
- 横截面特征缺失或无法在预测时点获得的证券；
- 为保证固定 `N` 维输入而追加的 padding 位置。

对于目标股票样本，还应保存 `target_cross_section_index`。训练时应验证：

```text
cross_section_mask[target_cross_section_index] == True
```

不成立说明目标股票没有进入该日横截面快照，不能把这个样本交给依赖横截面分支的模型。这样能避免“目标个股时序存在，但市场横截面里找不到它”的错位问题。

## Codex — 2026-07-16T06:41:57.153Z

这是一个“原始数值直接输入模型时，模型可能学到绝对规模，而不是走势形态”的问题。

例如两只股票走势完全一样：

```text
A: close  = 10 -> 10.5 -> 11
B: close  = 100 -> 105 -> 110
```

它们都是连续上涨 `5%`，但如果把原始 `close` 用全训练集统一的 `mean/std` 标准化，模型看到的仍是两个不同量级。模型可能据此学出“高价股/低价股”特征，而非“上涨 5% 的路径”。

成交量和成交额更严重：

```text
小盘股 amount = 5,000 万
大盘股 amount = 50 亿
```

两者都可能处于各自的“异常放量”状态，但统一全局 scaler 会把大盘股几乎永远放在大值区间，小盘股放在小值区间。模型难以自然识别“相对自身放量 2 倍”这种可迁移形态。

`0.5%-99.5% clipping` 还有第二层问题：它会把极大成交额截断到相同上限。对大盘股票，很多正常日可能已经落在截断区；模型既丢失细节，也会被全局流动性等级主导。

因此要区分两件事：

- **落盘值**：你要求的原始 `open/high/low/close/volume/amount`，保持不变，当前文档已经这样设计。
- **模型读入值**：不一定应直接做全市场统一标准化。

“个股因果滚动 scaler”的含义是，对每只股票在信号日 `t`，仅使用它自己过去窗口内的数据，例如过去 60 日：

```text
scaled_close(u) = (close(u) - mean(close[t-59:t])) / std(close[t-59:t])
scaled_amount(u) = (amount(u) - mean(amount[t-59:t])) / std(amount[t-59:t])
```

这样 A 和 B 的同样上涨路径会变得相似；“相对自身异常放量”的小盘股和大盘股也能被对齐。它是因果的，因为对 `t` 的样本只使用 `<= t` 的数据，不包含未来。

但不能直接断言个股 scaler 一定更好，因为绝对价格、流动性、市值代理本身也可能有预测价值。正确做法是保持原始数据不变，训练期比较：

```text
A. global_fold_scaler
B. causal_instance_scaler
C. 两路同时输入：个股标准化路径 + 原始字段的全局缩放版本
```

然后在 `validation_select` 比较 TopK、SELL 污染、自然分布 F1 和校准指标，冻结最优方案后才跑 prediction/forward。

当前方案已经写入 A/B 消融；如果你确认“原数据直给”也意味着**模型输入绝不做个股标准化**，那应删除 `causal_instance_scaler`，保留训练期全局 scaler 仅防止数值爆炸。
